## Bigint finding

The Python comparison separates arithmetic from decimal conversion:

| implementation / phase | F(1,000,000) |
| --- | ---: |
| gmpy2 (GMP) compute | **2.7 ms** |
| Python built-in compute | 36 ms |
| Python built-in compute + `str()` | ~514 ms |
| Lambda compute (Toom-3 + structural optimizations) | **~88 ms** |
| Lambda compute + base-1e9 output | **~95 ms** |
| Lambda compute before this work | ~706 ms |

The earlier finding was right that allocation/copy traffic was not dominant;
limb-loop throughput was.  The speedup was obtained without adding bigint
primitives or syntax: the compiler now emits reference-count fast paths inline,
borrows plain variables passed to `&` parameters, moves ownership through tail
calls, caches immutable array length/data fields, folds literal top-level
scalars, and the single-threaded pool is lock-free.  The library itself uses
direct `arrayi` operations, a dedicated Toom-3 multiplication/squaring above the cutoff, Karatsuba/schoolbook at the leaves, in-place
subtraction in the combine step, and tuned cutoffs.

Lambda is now ~2.5x Python's C-backed bigint on compute and ~5x faster on compute + decimal output,
because Python's decimal conversion costs ~440 ms.  GMP remains ~32x faster on
compute because it uses FFT multiplication and hand-tuned assembly; that is a
separate algorithmic step.
